## Список лидов

По умолчанию в интерфейсе сверху новые лиды (`created_at`, при равенстве `id`). Переключатель: «Сначала новые», «Сначала старые», «По последнему сообщению». Выбор и период хранятся в localStorage.

Период задаётся в блоке «Аналитика»: неделя (последние 7 дней), месяц (последние 30 дней, по умолчанию), прошлый календарный месяц, квартал (90 дней), год (365 дней), всё время или даты с–по. Список лидов фильтруется по дате добавления (`created_at`). Блок «Требуют внимания» периодом не фильтруется: там все активные, новые сверху.

Выручка за период — сумма платежей с `paid_at` внутри периода, независимо от даты лида. «Сумма сделок» — `deal_amount` клиентов и повторных, которые попали в счётчик периода. В счётчик «Клиентов» / «Повторно» лид входит, если у него есть платёж в периоде, либо он создан в периоде и платежей ещё нет. Импортированный сегодня клиент со старыми платежами в эту неделю не считается.

`GET /api/leads` без параметров по-прежнему отдаёт лидов по `id` по возрастанию и добавляет массив `payments`. Необязательный `?sort=` — `created_desc`, `created_asc` или `last_message`.

Платежи: `GET/POST /api/leads/{id}/payments`, `PUT/DELETE /api/leads/{id}/payments/{pid}`. Повторный POST с тем же `external_id` обновляет строку. Таблица `payments` создаётся при старте, существующие лиды не трогает. Удаление лида удаляет его платежи.

Карточка лида открывается по ссылке `#lead/<id>` (например `https://crm.flowcabinet.ru/#lead/15`). Хеш не требует отдельного маршрута на сервере. Клик по лиду в списке записывает этот хеш, закрытие карточки возвращает адрес списка. В шапке карточки кнопка «Скопировать ссылку». Если id нет в списке, показывается «Лид #<id> не найден», фильтры и сортировка не сбрасываются.

## Источник и причина отказа

Поля лида `source` и `rejection_reason`. Пустая строка — не заполнено. На `PUT /api/leads/{id}`, если поле не передано, уже записанное значение не затирается. Явная пустая строка или `null` очищает поле.

Коды источника (`source`):

| Код | Подпись |
| --- | --- |
| `avito` | Авито |
| `remontfranchiz` | сайт ремонтфраншиз.рф |
| `flowcabinet` | flowcabinet.ru |
| `telegram` | Telegram |
| `referral` | рекомендация/сарафан |
| `repeat_client` | повторный клиент |
| `tender` | тендер/генподрядчик |
| `other` | другое |

Коды причины отказа (`rejection_reason`):

| Код | Подпись |
| --- | --- |
| `price` | дорого/нашли дешевле |
| `timing` | сроки |
| `not_our_profile` | не наш профиль работ |
| `small_volume` | маленький объём |
| `no_response` | клиент пропал/не отвечает |
| `postponed` | отложили проект |
| `other_contractor` | выбрали другого подрядчика не по цене |
| `other` | другое |

Принимаются и код, и точная подпись. В базе хранится код. Неизвестный код — `400` `Unknown source` или `Unknown rejection_reason`.

Причина обязательна при создании лида сразу в сливе и при переводе в `drain_mql`, `drain_sql` или `drain_hot`. Ответ `400`, `detail`: `rejection_reason is required`. Старый слив, у которого причина ещё пустая, можно редактировать, не заполняя её. Для `other` нужен непустой `comment` (тот же комментарий лида, не отдельное поле). Иначе `400`, `detail`: `comment is required when rejection_reason is other`.

Новый лид из чата Авито получает `source=avito`.

Бот ставит источник и причину полями `source` и `rejection_reason`, не текстом комментария. Безопасный вызов: взять лида из `GET /api/leads/{id}` и отправить тот же объект в `PUT`, изменив нужные поля. Остальные поля `PUT` по-прежнему перезаписываются тем, что пришло в теле. Исключение — только `source` и `rejection_reason`: если их нет в JSON, остаётся записанное значение.

Для «другое» в теле `"rejection_reason": "other"` и непустой `"comment"`.

`GET /api/analytics/sources?period=month&start=&end=&today=` — тот же набор периодов, что у выручки (`week`, `month`, `prev_month`, `quarter`, `year`, `all`, `custom`). Считает лиды, созданные в периоде: `leads_by_source` (лиды и договоры), `rejections_by_reason`. Договор — статус `client` или `repeat`. Отказ — любой слив. Период «всё время» включает лиды без даты.

Миграция аддитивная: при старте CRM в `leads` добавляются `source` и `rejection_reason` (`TEXT NOT NULL DEFAULT ''`). Существующие строки не переписываются. Бэкфилл источника — отдельно, по умолчанию только печатает план:

```bash
python scripts/backfill_lead_source.py --dry-run
python scripts/backfill_lead_source.py --apply
```

## Соглашения
- Статусы лида: lead, mql, sql, hot, client, repeat, drain_mql, drain_sql, drain_hot
- Бюджеты: lo (<30к), mid (30-100к), hi (>100к)
- Типы объектов: Квартира, Коммерческая, Дом
- Даты `D.M.YY` и `DD.MM.YY`: год 00–99 читается как 2000–2099 (`2.12.25` → 2025-12-02)
